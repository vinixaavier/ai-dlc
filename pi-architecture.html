Pi — Arquitetura

Pi é um agente de IA minimalista e extensível para o terminal. Ele coordena requisições de modelos, execução de ferramentas, montagem de contexto e persistência de sessões — tudo em um único processo Node.js, com extensibilidade via TypeScript.

02O loop do agente (um "turno")

Cada turno começa com uma mensagem no ramo ativo e termina quando não há mais tool results pendentes nem mensagens enfileiradas.

1. MensagemA mensagem do usuário entra no ramo ativo (steering/follow-up entram em momentos específicos).
2. ContextoPi converte o ramo ativo em mensagens user/assistant/tool-result + system prompt + tools.
3. ProviderA requisição vai ao provider selecionado, que faz streaming da resposta do assistente.
4. FerramentasTool calls da resposta são executadas (podem ser paralelas); resultados são gravados na sessão.
5. DecisãoHá mais tool results ou mensagens enfileiradas? → começa outro turno.
6. FimSenão, a execução termina. Eventos de ciclo de vida notificam as interfaces.

↻ repete até ficar sem trabalho pendente

Controle em voo
  • Steering — entra depois do turno atual do assistente (e de suas tool calls).
  • Follow-up — entra só depois que o agente terminou o trabalho pendente.
  • Abort — para a execução atual e devolve as mensagens enfileiradas ao editor.
  • Se o SDK receber um prompt() durante streaming, é obrigado a declarar steer ou follow-up — nunca chuta.

03Sessões: uma árvore em JSONL

Cada sessão é um arquivo JSONL. Toda entrada tem ID e referencia o pai — o que forma uma árvore, não uma lista linear. Caminhar um caminho da raiz até uma folha é uma "ramificação".

entry-1 (mensagem do usuário) └── entry-2 (assistente + tool call) ├── entry-3 (tool result) → entry-4 (assistente) ← ramo abandonado └── entry-5 (resumo por compaction) └── entry-6 (assistente) ← folha ativa (ramo em uso)
Fork e clone

Continuar a partir de uma entrada anterior abre um novo ramo no mesmo arquivo. Fork/clone copiam o histórico selecionado para um arquivo de sessão novo — a história original nunca é destruída.

Compaction

Quando o contexto cresce demais, Pi insere uma entrada de resumo que substitui as mensagens antigas nas próximas requisições. As entradas originais permanecem na árvore, auditáveis.

Regra de ouro: o SessionManager é a fonte da verdade para o contexto de modelo finalizado. Restaurar histórico externo significa construir a sessão com um manager contendo essas entradas — atribuir mensagens direto em agent.state.messages não substitui o contexto persistido.

import { createAgentSession } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession();
try {
  const off = session.subscribe((ev) => {
    if (ev.type === "message_update" && ev.assistantMessageEvent.type === "text_delta")
      process.stdout.write(ev.assistantMessageEvent.delta);
  });
  await session.prompt("Explique este repositório");
  off();
} finally {
  session.dispose(); // aborta trabalho ativo, invalida extensões, remove listeners
}

Cada fronteira é substituível: modelRuntime, settingsManager, sessionManager (inclusive SessionManager.inMemory()) e resourceLoader.

06Extensões: TypeScript no mesmo processo

Uma extensão exporta um factory que recebe o ExtensionAPI. São carregadas via jiti (TS local sem passo de build) e rodam dentro do processo do Pi, com as mesmas permissões de SO.

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Saudação",
    handler: async (name, ctx) => ctx.ui.notify(`Olá, ${name || "mundo"}!`),
  });
  pi.on("tool_call", async (call, ctx) => { /* mutar input ou bloquear */ });
}

Ciclo de vida: factories async são aguardadas na inicialização; recursos de longa duração (servers, watchers, timers) devem começar em session_start e fechar em session_shutdown. agent_settled é o evento final e apenas-notificável — indica que o Pi não vai continuar sozinho.

07TUI: componentes, não strings brutas

O pacote @earendil-works/pi-tui dá um sistema de componentes ao terminal: cada componente renderiza linhas de terminal para a largura disponível e deve invalidar o cache quando estado ou tema mudam. A TUI coalesce as requisições de render.

Text / Markdown / Imageconteúdo Container, VStack, HStack, Boxlayout Input / Editortexto SelectList / SettingsListseleção ScrollViewrolagem Loader / CancellableLoaderprogresso ctx.ui.custom() + overlaytela/overlay efêmeros

Largura visível usa visibleWidth()/sliceByColumn() (ANSI, emoji e caracteres largos); teclado passa por matchesKey() + KeybindingsManager; cada interação custom deve ter caminho por teclado mesmo em modo fullscreen com mouse.

08Confiança e permissões

  • Trust é resolvido antes de carregar settings e recursos do projeto — extensões de projeto só participam de project_trust depois da decisão.
  • Ferramentas habilitadas usam as permissões de SO do processo do Pi — trust não faz sandbox de tool calls.
  • Extensões rodam dentro do processo e enxergam prompts, tool calls, arquivos e credenciais: só carregue extensões de fontes confiáveis.
  • Para arquivos/repositórios não confiáveis ou automação não supervisionada, revise a documentação de segurança antes.
