ai-dlc · Agent Factory

Plataforma local de construção e execução de agentes no modelo de ator, rodando em Kind, gerenciada por GitOps.

Visão geral

Substrate (ator) GPU / modelo Observabilidade GitOps — fluxo principal

Componentes

Agent Substrate

Namespace ate-system. Runtime de modelo de ator: agentes rodam como atores sandboxados em gVisor (ateom-gvisor), alocados por worker pools. Ciclo de vida via ATE API: spawn → execução → suspend com snapshot do estado na storage de objeto (rustfs) → restore sob demanda. Rede do ator passa por atenet-router + atenet-egress (proxy com ext_proc).

kagent

Namespace kagent. Controller k8s + runtime Go ADK + UI. Declara agentes por CRD: Harness (runtime de execução — por ex. BYO image do ADK), AgentTemplate (especialização: prompt, modelo, label selector do harness), ModelConfig e RemoteMCPServer. Com substrate habilitado, o controller gera o workload e alocá-lo em atores do worker pool kagent-default com snapshot policy própria.

llm-runtime

Namespace sglang. SGLang ou vLLM (selecionável por values.runtime) servindo Qwen 3.8-27B NVFP4 na RTX 5090. GPU injetada via CDI do NVIDIA (GPU Operator gerencia device plugin + DCGM). Atrás do AgentGateway em /v1.

AgentGateway

Namespace agentgateway-system. Router central: API compatível OpenAI (/v1/chat/completions), Anthropic (/v1/messages) e Codex (/v1/responses), gateway A2A (agentes expostos em aigw.localhost/<agente>), roteamento MCP e analytics de uso de LLM em postgres próprio. É por ele que todo tráfego de LLM e A2A dos agentes e harnesses passa.

Harnesses

Wrap CLIs de agente atrás do AgentGateway como agentes de fábrica: pi-harness (Pi coding agent), codex-harness, claude-harness e adk-harness (agent Go ADK dentro do Substrate, via CRD Harness). Cada um é um Argo Application em argocd/apps/.

AgentRegistry

Discovery declarativo de agentes e servidores MCP (ar.dev/v1alpha1). Catálogos aplicados via /v0/apply por hook do Argo (não é CRD). Descreve os agentes A2A em execução (kagent-catalog.yaml) para clientes descobrirem quem está exposto no gateway.

Observabilidade

OTel Collector (otel) recebe traces/métricas/logs em :4317; Tempo guarda traces (TraceQL), Prometheus cobre métricas (job substrate raspando :9090 dos pods de ate-system), Loki guarda logs; Grafana une tudo. Todos os agentes, harnesses e o substrate exportam OTel — cada interação de ator fica rastreável.

GitOps / Platform

Gitea hospeda o repo; Argo CD reconcilia os charts OCI da pasta platform/ (pacotados pelo bootstrap no registry in-cluster). Ownership dividido em agentgateway-platform, kgateway-platform e agentregistry-platform. kgateway faz o roteamento HTTP local (*.localhost) e o registry in-cluster serve imagens e charts via HTTP.

Ciclo de vida do ator

  1. Declarar Harness + AgentTemplate no namespace kagent (GitOps → Argo → controller).
  2. O controller kagent resolve o harness e cria o workload no Substrate: um ator gVisor do worker pool kagent-default.
  3. O ator inicia o runtime ADK; o estado inicial é persistido como snapshot (gs://ate-snapshots/kagent/…) e reaproveitado em restaurações — cold start quase zero.
  4. Quando o ator fica ocioso, é suspenso imediatamente após agent_end (flush de OTel incluso); a restauração do snapshot é o que atende a próxima requisição.
  5. Requisições de LLM saem pelo egress do atenet, chegam no AgentGateway e no SGLang; cada etapa gera span (traceparent propagado).

Fluxo de trace (caminho canônico)

Agente → AgentGateway → kagent → Go ADK → AgentGateway /v1/chat/completions → SGLang
Export in-cluster: http://otel-collector.otel.svc.cluster.local:4317 · inspeção: Grafana Explore / Tempo TraceQL.
