01 O modelo mental

kagent é um Operator Kubernetes. Ele observa CRDs como Harness e AgentTemplate, valida o estado desejado e cria ou atualiza os componentes necessários para que o agente exista e possa atender requisições. O código do agente não é o Operator: ele roda no runtime, dentro da infraestrutura definida pelo Harness.

K8s

Declaração

O usuário descreve intenção em YAML. O Kubernetes guarda o estado desejado e dispara reconciliações.

↻

Operator

O controller do kagent traduz CRDs em workloads, configurações, rotas e agentes prontos para execução.

AI

Agente

A instância recebe contexto, conversa com o modelo e usa ferramentas autorizadas pelo template.

ATE

Substrate

Provisiona actors efêmeros ou restaurados de snapshot dentro de uma sandbox, como gVisor.

02 Arquitetura em camadas

A separação importante é entre controle, definição, execução e isolamento. O kagent conecta Kubernetes ao Substrate; o Substrate não decide a personalidade do agente.

03 Cada etapa, em ordem

01

Runtime

É o processo que executa o loop do agente: ADK, Pi, Codex ou Claude, por exemplo. Ele recebe mensagens, chama o LLM e executa tools.

02

Sandbox

É a fronteira de isolamento do processo. O Substrate pode usar um actor gVisor para separar filesystem, namespaces, rede e execução do ambiente do cluster.

03

Harness

É o contrato operacional reutilizável: imagem imutável, comando, env, política de snapshot, WorkerPool e quais templates são permitidos.

04

AgentTemplate

É a definição da identidade do agente: system prompt, model config, descrição e referências de ferramentas. Um template é uma receita, não um processo.

05

Agent Instance

É a instância concreta criada para atender uma sessão ou workload. Ela combina um template com um runtime e um actor alocado pelo Substrate.

06

Tools e modelo

As tools são a capacidade de agir (MCP, Kubernetes, Grafana). O modelo fornece raciocínio; o agente decide quando usar cada ferramenta.

Distinção essencial: o Harness define “onde e como” o agente roda; o AgentTemplate define “quem é” o agente; a Agent Instance é o resultado vivo dessa combinação.

04 O fluxo de uma requisição

A reconciliação acontece antes do tráfego. Uma vez que o estado está pronto, cada interação percorre o runtime e retorna pelo gateway.

01 · ClienteChat, A2A, API OpenAI ou evento.
02 · GatewayRoteia para o agente.
03 · OperatorGarante o estado desejado.
04 · InstanceActor é criado ou restaurado.
05 · RuntimeLoop do agente processa o pedido.
06 · Tools / LLMExecuta ações e consulta o modelo.
07 · RespostaRetorna com logs e traces.
Observabilidade: kagent e os runtimes exportam logs e traces via OTLP. Isso permite correlacionar gateway → controller/runtime → tool → modelo em uma única investigação.

05 Como isso aparece no Kubernetes

Harness: infraestrutura e política

kind: Harness
spec:
  workload:
    image: .../golang-adk@sha256:...
    command: ["/app"]
  substrate:
    workerPoolRef:
      name: kagent-default
    snapshotPolicy:
      location: gs://ate-snapshots/...

AgentTemplate: comportamento

kind: AgentTemplate
metadata:
  labels:
    kagent.dev/runtime: hello-substrate
spec:
  modelConfig:
    name: default-model-config
  systemPrompt: ...

O que o Operator reconcilia

  • Seleciona o Harness compatível com o label/runtime do template.
  • Prepara o workload e a conexão com o Substrate API.
  • Aloca ou restaura o actor no WorkerPool escolhido.
  • Aplica a imagem, prompt, model config e ferramentas permitidas.
  • Expõe o agente e mantém status, saúde e telemetria coerentes com o estado desejado.
